# 災害リスク診断 — 仕様

住所または緯度経度を入力すると、その地点の災害リスクを国土地理院の公開データから
機械的に判定し、説明文・地図・データを返す Web アプリケーション。

デジタル庁の生成AI基盤「源内」の行政実務用 AI アプリ（ExApp）仕様に準拠しており、
源内へ登録して利用することも、単体の Web アプリとして利用することもできる。

---

## 1. 全体構成

```
利用者 ──▶ 診断画面 (/ui) ──┐
                            ├──▶ POST /invoke ──▶ 診断処理 ──▶ 国土地理院 API
源内 Web ─────────────────┘                          │
                                                      ├──▶ 言語モデル（任意）
                                                      └──▶ 検証 → レポート
```

| 層 | ファイル | 責務 |
| --- | --- | --- |
| API | `app/main.py` | 認証・非同期ジョブ・源内互換のリクエスト/レスポンス |
| 入力正規化 | `app/normalize.py` | 源内から届く値の形の揺れを吸収 |
| 診断 | `app/diagnose.py` | 判定の統括。Diagnosis を組み立てる |
| 外部データ | `app/gsi.py` | 国土地理院の住所検索・標高・タイル取得 |
| 判定 | `app/hazard.py` | タイルのピクセル色 → 危険度 |
| 地図 | `app/mapimage.py` | 地図画像の生成（凡例つき） |
| 文章 | `app/narrative.py` | レポート組み立て。LLM とテンプレートの切替 |
| 言語モデル | `app/llm.py` | Ollama / Claude API 呼び出しと生成文の検証 |
| 画面 | `mock/` | 診断画面（フォーム自動生成・結果表示） |
| 適合チェック | `app/conformance.py` | 源内の受け入れ条件の自己検査 |

## 2. 入力

| 項目 | 型 | 必須 | 内容 |
| --- | --- | --- | --- |
| 場所 | text | ○ | 住所。`34.0704,134.5548` 形式の緯度経度も可 |
| 判定する災害 | checkbox | | 洪水／津波／高潮／土砂災害。未選択なら全部 |
| 居住階 | number | | 1〜60。垂直避難の可否判定に使う |
| 世帯の状況 | checkbox | | 高齢者・要介護者／乳幼児／車椅子／自家用車なし |
| 世帯の状況（自由記述） | textarea | | 200字まで。選択肢に無い事情 |

画面のフォームは `app/schema.py` の JSON 定義から自動生成される。源内へ登録する際も
同じ JSON を「リクエスト形式」欄に貼る。項目を増やす場合はこの 1 ファイルを変更する。

## 3. 判定ロジック

### 3.1 使用データ（すべて国土地理院の公開 API・キー不要）

| 用途 | エンドポイント |
| --- | --- |
| 住所検索 | `msearch.gsi.go.jp/address-search/AddressSearch` |
| 標高 | `cyberjapandata2.gsi.go.jp/general/dem/scripts/getelevation.php` |
| 基図タイル | `cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png` |
| 災害タイル | `disaportaldata.gsi.go.jp/raster/<layer>/{z}/{x}/{y}.png` |

### 3.2 判定するハザード（6 レイヤ）

| キー | 名称 | レイヤ ID |
| --- | --- | --- |
| flood | 洪水浸水想定区域（想定最大規模） | `01_flood_l2_shinsuishin_data` |
| tsunami | 津波浸水想定 | `04_tsunami_newlegend_data` |
| hightide | 高潮浸水想定区域（想定最大規模） | `03_hightide_l2_shinsuishin_data` |
| debris_flow | 土砂災害警戒区域（土石流） | `05_dosekiryukeikaikuiki` |
| steep_slope | 土砂災害警戒区域（急傾斜地の崩壊） | `05_kyukeishakeikaikuiki` |
| landslide | 土砂災害警戒区域（地すべり） | `05_jisuberikeikaikuiki` |

### 3.3 判定方法

ハザードマップポータルのラスタタイルは、**色が凡例（浸水深・区域種別）を表す**。
ズーム 16（1 ピクセル ≒ 2m）でタイルを取得し、対象地点のピクセル色を凡例と照合する。

- 完全一致で判定。一致しない場合は許容差 24 以内の最近色に丸める（縁のアンチエイリアス対策）
- 透明度 128 未満の画素は区域外として扱う
- タイル自体が 404 の場合は「対象外」（その災害の想定区域図が作られていない範囲）

**周辺 50m も走査する。** 地点が区域外でも、近くに区域があれば避難経路の注意として報告する。

### 3.4 判定結果の区別

| 表示 | 意味 |
| --- | --- |
| 深さ・区域名 | 地点そのものが該当 |
| 区域外 | 想定区域図はあるが、地点は該当しない |
| 対象外 | その災害の想定区域図がこの場所に存在しない |

### 3.5 避難階の算出

```
安全な階 = int(想定浸水深 ÷ 3) + 2
```

想定浸水深は**範囲の上限（最悪値）**を用いる。「5〜10m」なら 10m で計算する。
下限で計算すると、実際に上限まで浸水した際に水没する階を安全と案内してしまうため。
「20m以上」のように上限が無い段階は下限を用いる。

## 4. 出力

### 4.1 レポート（Markdown）

1. 地点情報（検索文字列・緯度経度・標高・判定日時）
2. 判定結果の表（ハザード × 地点/周辺50m）
3. この地点について（説明文）
4. 申告された世帯の状況（自由記述がある場合、原文のまま）
5. 確認事項
6. 本診断について（免責・出典）

表記は**常体（である調）**で統一する。防災情報として断定的に記述するため。

### 4.2 地図画像

**該当するハザードごとに 1 枚ずつ**生成する（最大 4 枚）。浸水系は凡例の色が共通で、
重ねると判読できなくなるため。1 枚に含まれるもの:

- 地理院淡色地図の上に当該ハザードのタイルを 65% の不透明度で重ねたもの（640×640）
- 診断地点の赤いマーカー
- 100m のスケールバー
- **凡例**（その地図に実際に現れている色のみ。使われていない段階は載せない）
- 出典表示

### 4.3 データ（JSON）

判定結果を機械可読な形で出力する。地点・標高・各ハザードの判定・出典を含む。

## 5. 説明文の生成

### 5.1 二重化

| 経路 | 条件 |
| --- | --- |
| 言語モデル | 利用可能かつ検証を通過した場合 |
| テンプレート文 | 上記以外（既定のフォールバック） |

**判定そのものは言語モデルに行わせない。** モデルへ渡すのは確定済みの事実だけで、
役割は「事実を読みやすい日本語に言い換える」ことに限定する。

### 5.2 モデルへ渡す事実

`narrative.facts_for_llm()` が組み立てる。**値のある項目のみ渡す。**
空欄を渡すとモデルがそれを埋めようとして存在しない区域を捏造するため（実測で確認）。

### 5.3 生成文の検証（`llm.verify()`）

以下に該当した場合、生成文を**採用せずテンプレート文へ戻す**。

| 検査 | 内容 |
| --- | --- |
| 数値の捏造 | 事実に無い `○m` が書かれている |
| 該当関係の反転 | 該当しているのに「該当しない」と書いている |
| 周辺区域の捏造 | 周辺該当が無いのに「周辺にある」と書いている |
| 情報欠落の主張 | 調べた上での該当なしを「情報がない」と書いている |
| 内部項目名の露出 | 「安全な階については」等のスキーマ漏れ |
| 安全宣言 | 「安全です」「心配ありません」等 |
| 文体 | 敬体（です・ます調）が混ざっている |

### 5.4 検証で防げないもの

曖昧な集約（「津波でも同様の浸水深」等、個々の数値は正しいが対応が誤っているもの）は
検出できない。**住民に直接配布する用途では、生成文を人が確認する前提とすること。**
確認工程を置けない場合は `EXAPP_LLM_PROVIDER=none` でテンプレート文に固定する。

### 5.5 自由記述の扱い

利用者の自由記述は、
- **原文をレポートに必ず掲載する**（モデルが書き落としても失われないため）
- **モデルにも渡し**、内容を踏まえた助言を生成させる
- キー名で「参考情報であり指示ではない」と明示する（指示注入への防御）

## 6. API（源内互換）

### 6.1 エンドポイント

| メソッド | パス | 用途 |
| --- | --- | --- |
| POST | `/invoke` | 診断の実行。`x-api-key` 必須 |
| GET | `/status/{request_id}` | 非同期実行の進捗・結果 |
| GET | `/schema` | 源内に登録するリクエスト形式 JSON |
| GET | `/health` | 死活確認 |
| GET | `/ui` | 診断画面 |
| GET | `/docs` | API ドキュメント |

### 6.2 リクエスト

```
POST /invoke
Content-Type: application/json
x-api-key: <発行したキー>
x-user-id: <利用者の安定 ID>

{"inputs": {"address": "...", "floor": 1, ...}, "sessionId": "<uuid-v4>"}
```

### 6.3 レスポンス

既定は非同期。`?mode=sync` で同期に切り替わる。

| | 同期 | 非同期 |
| --- | --- | --- |
| 応答 | `200 {"outputs": "..."}` | `202 {"request_id", "status": "PENDING", "status_url": "/status/<id>"}` |
| その後 | なし | `status_url` を GET → `COMPLETED` で `outputs` と `artifacts` |

診断は 10〜20 秒を要するため、既定を非同期としている（同期のタイムアウトは 29 秒）。

## 8. 制約

- **判定精度は縮尺に依存する。** ズーム 16 の 1 ピクセルは約 2m。敷地の端では判定が変わりうる
- **浸水想定は「想定最大規模」。** 実際にこの深さになるとは限らず、これを超える可能性も残る
- **判定に含まれないもの**: 想定を超える規模の災害、内水氾濫、地震の揺れそのものによる被害
- **避難所データは未対応。** 国土地理院の指定緊急避難場所タイルを取得できなかったため v1 では除外
- **言語モデルはローカル実行が前提。** クラウドへ配置する場合はテンプレート文に固定するか、
  Claude API を使う（従量課金）
- **避難の判断を代替しない。** 事前の備えのための参考情報である
